# 静态检查

[English](CHECKING.md)

`velin check` 在解析和编译之后运行，不修改字节码。检查器是保守的：只有能证明的问题才会报，这样宿主驱动的合法脚本不会被猜测误杀。

```sh
cargo run -p velin-cli -- check examples/adventure.velin
```

编辑器 LSP 和 Playground 的检查按钮使用同一套分析。

## 检查器能证明什么

两趟独立分析共用一种 `Diagnostic`：

1. **类型推断**，论域是 `Integer`、`Boolean`、`String`、`List`、`Record` 和 `Unknown`。
2. **确定赋值**：只有每个可达前驱都赋值过，变量才能被读取。

不可达代码不会被检查。诊断使用从 1 开始的行列，并指向表达式节点。

## 类型与 Unknown

`default` 决定入口类型。赋值沿控制流图传播。汇合时只有每条入边类型一致，才会保留具体类型。

下面这些会变成 `Unknown`，而不会误报：

- 绑定 `perform` 返回的值。
- 冲突的分支类型（一条路径是 `1`，另一条是 `"x"`）。
- 否则需要猜测类型的循环回边。

`Unknown` 与任何上下文兼容。后面若能确定用错（`not "x"`）仍会报；后面若对宿主返回值可能合法，则不报。

`if` 和 `while` 的条件会报告已知的非布尔。那里允许 `Unknown`，因为宿主可能返回布尔。

## 确定赋值

`default` 名字在入口处已赋值。汇合时，只有每个可达前驱都赋值过，才认为变量已赋值。

```velin
if ready:
    set score = 1
perform say(score)
```

若 `ready` 可以为假，`score` 并非每条路径都赋值，`check` 会报告这次读取。

## 错误与警告

只有被标成错误的诊断才会让 `velin check` 失败（退出码 1）。仅有警告不会。调用 `check_script` 的宿主应在任何诊断 `is_error()` 时拒绝 `run`。

检查器从不插入运行时陷阱，也不改程序计数器。通过检查的脚本仍可能在运行时失败：溢出、缺失的列表下标、宿主提供的值，都不在静态分析能证明的范围里。

## 它抓不到什么

- 某个宿主命令名是否实现。
- 宿主命令的参数个数和类型（名字是不透明的）。
- 会 `perform` 的“无限”循环（那些会让出；从不让出的循环由立即 fuel 预算截断）。
- 只有宿主恢复之后才非法的值。

这些属于[宿主协议](HOST.zh-CN.md)和[资源预算](LIMITS.zh-CN.md)。
