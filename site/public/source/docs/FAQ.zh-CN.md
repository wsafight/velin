# 常见问题

[English](FAQ.md)

围绕嵌入 Velin、编写脚本，以及和其他语言对比时最常出现的问题。

## Velin 适合做什么

Velin 是一门小型脚本语言，给需要**规则、状态和控制流**、又不想把整个应用交给脚本的宿主使用。

常见宿主包括：

- 互动叙事、对话和任务。
- 必须可回放的游戏或产品规则引擎。
- 必须在预算内失败的用户扩展。
- 需要在浏览器里解析、检查并运行、且不依赖服务端的演示。

脚本不能打开文件、绘制界面或访问网络。它让出一个宿主命令，由嵌入方决定该命令的含义。

## 什么时候不该用

出现以下需求时请换别的工具：

- 需要模块、类或大型标准库的通用编程。
- 脚本内部要做浮点运算、读时钟或调用操作系统 API。
- 需要稳定的公开语言和 Rust API。Velin `0.x` 仍处于预稳定阶段。

Lua、Rhai、JavaScript 和 WASM 宾客更适合开放式扩展。Velin 更窄：确定性的值、保守的检查，以及单一的宿主效果协议。

## 为什么没有浮点类型

整数运算是带检查的，且不依赖平台。浮点会让相等比较、显示、快照和跨目标回放受舍入模式与 CPU 细节影响。

宿主如果需要真实世界的单位，把它们留在 Velin 之外：先换成整数（分、毫米、毫秒）再交给脚本，或在宿主命令里做换算。

## Velin 是一门 Rust 语言吗？

不是。Velin 是写规则的脚本语言。运行时用 Rust 写成，其中一种嵌入路径是 `velin` crate，但脚本不是 Rust，也不面向 Rust 程序员。

同一套管线也会编译成 WebAssembly。页面可以从 JavaScript 调用 `check` 和 `run`。见 [WebAssembly](WASM.zh-CN.md)。

## `say` 和 `ask` 是语言关键字吗？

不是。它们只是 CLI 参考宿主和浏览器 Playground 的约定。语言里只有 `perform`。命令名会被驻留成不透明的 `host_id`。

游戏宿主可以直接绑定 `perform open_door("east")` 或 `choice = perform show_menu(options)`，不必让 Velin 认识门或菜单。

## 为什么必须用四个空格缩进

语句前端拒绝制表符，并且每层必须恰好四个空格，这样编辑器、diff 和诊断里的嵌套不会产生歧义。没有可选的花括号写法。

## 随机数如何回放

`random(low, high)` 和 `chance(percent)` 读取机器帧里的伪随机数生成器。`Machine::new` 使用种子 `0`；`Machine::with_seed` 设置显式种子。克隆机器会复制尚未消耗的随机序列，所以快照也会回退之后的掷骰。

脚本不能读取系统熵、墙上时钟或线程局部随机状态。

## 不信任的脚本会不会接管宿主？

脚本自己不能做 I/O，并且每一层都有预算：源码大小、AST 深度、值、字节码和立即执行步数。没有 `perform` 的循环会在 10,000 条立即指令后停止。

宿主仍然是信任边界。它必须允许名单命令名、检查参数，并施加自己的时间、输出和权限限制。详见[宿主协议](HOST.zh-CN.md)。

## 能不能保存正在运行的脚本？

`Machine` 实现了 `Clone`。克隆是程序计数器、变量、挂起的宿主效果、完成标志和 RNG 的内存快照，不是稳定的磁盘格式。

如果序列化 `Program`，反序列化会在运行前校验字节码。在项目给出兼容承诺之前，不要把当前快照布局当成长期存档格式。

## 能在浏览器里运行吗？

可以。`velin-wasm` 向 JavaScript 暴露 `check` 和 `run`。站点上的 Playground 加载该包，源码不会发送到服务端。桌面 CLI 使用同一套解析器、检查器、编译器和 VM。

## 语言稳定吗？

还不稳定。`0.2.1` 已经发布，但在 `0.x` 阶段，语法、序列化程序格式和 Rust API 仍可能变化。[架构](ARCHITECTURE.zh-CN.md)描述了项目打算如何演进：VM 不做 I/O、值必须确定、检查保持保守，任何外部行为都走宿主效果。

## 从哪里开始？

1. 先跑[示例与写法](EXAMPLES.zh-CN.md)或 [Playground](PLAYGROUND.zh-CN.md)。
2. 把[语法速查](CHEATSHEET.zh-CN.md)放在手边；遇到语法再查[语言参考](LANGUAGE.zh-CN.md)。
3. 用 [Rust 嵌入指南](EMBEDDING.zh-CN.md)、[WebAssembly](WASM.zh-CN.md)和[宿主协议](HOST.zh-CN.md)接入应用。
4. CLI 和 LSP 见[工具链](TOOLING.zh-CN.md)。
