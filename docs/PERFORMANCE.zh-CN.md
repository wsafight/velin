# 性能设计

[English](PERFORMANCE.md)

Velin 采用“编译为字节码，再由 VM 执行”的模型。源码只在编译阶段解析；生成的 `Program` 可以复用，用来创建多个 `Machine` 或多次执行。程序由两层指令组成：

- `Op` 负责赋值、跳转、宿主调用和停止等控制流。
- `ExprOp` 是表达式栈机指令，负责常量、变量读取、运算、built-in 和短路逻辑。

完整路径如下：

```text
源码 -> 行扫描与表达式解析 -> AST -> lowering -> Program -> 字节码验证
                                                       |-> 静态检查
                                                       +-> Machine -> VM 执行
```

这种分层让解析、静态分析和运行时各自保持清晰边界。性能设计以语义正确和可维护性为前提，主要目标是减少重复工作、让常见路径保持线性，并使资源消耗可预测。

## 设计原则

### 语义只有一个来源

算术、比较和 built-in 的行为集中在 `velin-eval`。编译期常量折叠、普通表达式执行和 VM 的专用路径都复用这些语义。专用路径只负责识别操作数和管理所有权，不重新实现语言规则。

这样可以防止编译器与 VM 在溢出、除零、类型错误、缺失键等边界上产生不同结果。

### 专用路径必须有通用回退

编译器和 VM 只对结构明确、收益稳定的形式做特化。表达式不满足条件时，继续走完整的表达式字节码和 evaluator。优化点因此是局部的，不会扩散成第二套执行系统。

### 失败不能破坏状态

集合和字符串的原地更新包含两个阶段：

1. 求值并检查所有可能失败的操作，包括类型、索引、整数溢出和资源预算。
2. 检查通过后取出目标槽位，更新值并写回指标。

因此 `push`、`put`、`remove` 或字符串追加失败时，原槽位保持不变。这个顺序是运行时语义的一部分，不能为了减少分支而省略。

### 资源边界优先于极限吞吐

源码、表达式、字节码、值树、机器状态和宿主载荷都有明确上限。上限既防止异常输入造成无界工作，也让验证器、检查器和 VM 可以安全地使用紧凑索引与预分配。

## 解析与输入扫描

### 行扫描借用源码切片

语句解析前先对源码做一次物理行扫描。缩进只允许 ASCII 空格，因此前导缩进按字节读取；遇到制表符会立即报错。`Line` 保存行号、缩进级别、列号和指向原源码的 `&str`，不会为每一行复制正文。

注释处理先检查当前行是否包含 `"` 或 `#`。没有这些字节时直接返回原切片；只有可能包含字符串或注释的行才进入完整状态扫描。完整扫描同时正确处理转义字符和字符串插值中的 `#`。

源码文件限制为 1 MiB、10,000 个物理行和 64 层语句嵌套。这些限制在构造大型中间结构前检查。

### 短表达式使用栈内 token

表达式 lexer 的前 4 个 token 存放在固定数组中。短表达式不需要为 token 容器申请堆内存；超过容量后，已有 token 一次性迁移到 `Vec`，后续解析仍使用同一套接口。

这是小容量内联存储，不改变语法结构，也没有为短表达式单独维护解析器。

### 嵌套插值共享解析预算

单次表达式限制为 64 KiB、512 个 token 和 32 层括号嵌套。字符串插值中的子表达式共享累计字节数与累计 token 数预算，避免嵌套输入反复触发接近上限的扫描。

宿主调用参数直接按逗号分隔的表达式列表解析，并保留每个参数的源码 span。这里不会先拼接一个虚构的 `list(...)` 再重新解析。参数数量与语言中的宽参数边界一致，最多为 128 个。

## 静态分析

### 名称在边界处转换为槽位

`SlotTable` 在 lowering 时把变量名驻留为 `u32` 槽位。确定赋值分析和 VM 指令直接携带槽位；类型检查保留带 span 的源码表达式，在读取变量时通过 `SlotTable` 找到槽位，再访问密集状态数组。生成诊断时可以用反向表恢复变量名。

类型传播状态使用 `Vec<Type>`，确定赋值状态使用位集合。公开 API 提供的名称环境会先转换为槽位入口状态，基本块之间只复制或合并密集状态，不重建名称环境。

### 直线代码单遍处理

没有跳转的程序不构建控制流图。若类型检查点已经按程序计数器排序，类型传播会在一次指令扫描中同时消费检查点；确定赋值分析也直接维护一个当前位集合。

这条路径覆盖顺序赋值和宿主调用等普通脚本，同时保留完整诊断位置。

### 分支按基本块传播

包含跳转的程序先划分基本块，并建立前驱、后继和可达性。数据流状态只在块边界传播：

- 确定赋值是 must analysis，合流时对前驱状态取交集。
- 类型分析仅在所有到达路径给出同一具体类型时保留该类型，否则回到 `Unknown`。
- 工作队列只在块的输入状态发生变化时重新加入后继。

检查器只报告能够证明必然有问题的类型用法；`Unknown` 保持宽容。这一保守规则比追求更激进的静态推断更重要，因为它避免拒绝运行时可能合法的脚本。

### 短路表达式只检查可达读取

`and` 和 `or` 在表达式字节码中使用前向跳转。确定赋值分析用抽象栈跟踪布尔常量、非布尔值和未知值，从而排除被常量短路屏蔽的变量读取。

常见抽象栈的前 8 项存放在固定数组中，较深表达式才转入 `Vec`。无分支表达式直接扫描；合法的前向分支按程序计数器单遍传播状态。独立调用分析 API 时若收到非规范分支，则使用工作队列求不动点，保证通用接口不会依赖编译器输入。

每个表达式 chunk 的可达 `Load` 集合会在一次检查中缓存，状态表和队列也在不同 chunk 之间复用。

### built-in 类型参数使用小数组

类型推断处理 built-in 时，前 4 个参数类型存放在栈内数组；宽参数调用才构造 `Vec<Type>`。两条路径最终调用同一个 `infer_builtin`，所以只是存储策略不同。

## 编译与字节码

### 表达式使用连续 arena

`Program` 把所有表达式操作和常量分别存入连续的 `expr_ops` 与 `constants` arena。`ProgramChunk` 只保存两个范围和源码行号。VM 通过范围借用切片，不需要为每次表达式求值组装指令对象。

`ProgramBuilder` 持有一个可复用的 `ExprChunk` scratch。每个表达式编译完成后，其内容移动到 arena，scratch 的容量留给下一个表达式继续使用。程序完成时，各主向量执行 `shrink_to_fit`，避免长期保留构建阶段的额外容量。

当前 64 位目标上，布局测试固定 `ExprOp` 为 12 字节、`Op` 为 32 字节、`ProgramChunk` 为 20 字节。尺寸测试用于及时发现枚举字段或冷路径载荷意外扩大热指令流。可变长度的宿主参数放在 `Box` 中，使普通 `Op` 不承担其内联尺寸。

### 常量折叠保持保守

编译器只折叠能够通过 `velin-eval` 成功求值的纯常量子树。随机调用不参与折叠；整数溢出、除零、类型不匹配等失败候选保留为普通字节码，在运行时按原求值顺序报错。

短路逻辑也遵循同一原则。若常量左值已经决定结果，不可达分支不会分配随机状态槽位；若不能确定，则保留完整短路结构。

### 直线代码传播常量

`ProgramBuilder` 在组装直线代码时记录 `SetConst` 和 `CopySlot` 写入的值。后续赋值会基于这组小型已知值环境求值；纯表达式成功时直接变成另一个 `SetConst`，运行时不再进入表达式求值。遇到跳转、宿主 effect、未知写入或终止指令时清空环境，因此不会跨越路径合流或外部 effect 传播。求值失败、随机调用和可能在运行时出错的候选仍保留原字节码及错误时机。

已知值环境同时维护槽位到名称的增量映射。宽直线脚本不会在每次赋值时从全部槽位重新构建 `BTreeMap`；跳转、宿主 effect 和未知写入仍会清空这份环境。

### 直接指令只覆盖明确形状

lowering 会把下列常见结构表示为直接指令：

| 源码形状 | 字节码表示 | 原理 |
| --- | --- | --- |
| 常量赋值 | `SetConst` | 直接安装常量及其预计算资源指标 |
| 变量复制 | `CopySlot` | 按槽位读取，并复用源槽位指标 |
| `count = count + 常量` | `Update::AddInteger` | 在槽位上完成检查加法 |
| `slot <op> 整数字面量` 条件 | `JumpIfIntegerCompare` | 直接读取整数槽位并决定跳转 |
| 对自身的 `push`、`put`、`remove` 或 `+` | `Update` | 保留目标值所有权，执行预检后更新 |

识别条件限定在语义完全等价的形状。其他赋值和条件仍引用表达式 chunk，因此新增语言特性时只需先维护通用路径，再决定是否值得加入特化。

### 控制流保持稳定的程序计数器

常量布尔条件可转换为直接跳转，无条件跳转链会解析到最终目标。处理过程不删除或重新编号指令，因此静态检查保存的 PC、源码位置和 host site 映射保持稳定。

### 循环尾部合并为一次 VM 步进

VM 会识别紧邻的 `Update` 和无条件 `Jump`，这是计数循环通常生成的尾部。一次 dispatch 内完成更新并选择跳转目标。步数预算仍按两条原始指令计入，因此循环上限和无限循环诊断不变。这只是运行时 dispatch 优化，公开字节码结构和验证规则保持不变。

## 字节码验证与执行准备

### 外部字节码先完整验证

`Program` 是公开且可序列化的结构，不能假设所有实例都来自当前编译器。`ValidatedProgram` 表示已经检查过的共享 `Arc<Program>`，验证内容包括：

- 指令、chunk、槽位和参数数量上限；
- 槽位、常量、chunk 与跳转目标的索引范围；
- 表达式每条路径的栈高度和最终单值结果；
- 常量值树与程序文本预算；
- 更新指令和 built-in 的参数合法性。

`Machine::new` 和 `Machine::with_seed` 接受普通程序时执行完整验证。`ScriptRunner` 可以复用 `CompiledScript` 的验证证明；如果调用方替换了公开的 `program` `Arc`，指针身份不再一致，运行器会重新验证。

这里保留显式的安全边界，不以调用约定代替验证。

### 执行元数据按需初始化

验证后的程序通过 `OnceLock` 延迟构造 `ExecutionMetadata`。只做编译或静态检查的调用方不承担运行时元数据成本；第一个 `Machine` 构造元数据，后续机器共享它。

元数据记录每个表达式的最大栈深、是否修改随机状态、是否直接继承槽位指标、常量结果指标、源码行号，以及可直接寻址的 built-in 调用计划。这些信息在程序生命周期内不变，不需要每次执行重新分析字节码。

## VM 执行

### 操作数栈跨表达式复用

`Machine` 持有一个 `expression_stack`。每次求值先清空长度，再按验证阶段得到的最大栈深补足容量。执行过程中不会复制指令，`ExprOp` 和常量都从 `Program` 的 arena 借用。

直线标量表达式在机器构造完成后通常只进行栈 push/pop，不需要重复创建操作数容器。

### 长标量表达式可使用寄存器计划

执行准备阶段会识别只包含常量、槽位读取、一元运算和普通二元运算的长表达式，并为其生成非序列化的寄存器计划。每个中间值拥有稳定的临时寄存器，求值时按索引读取操作数，不必为每个中间结果维护表达式栈。计划保存在执行元数据中，由已验证的表达式 chunk 重新构建，不改变序列化字节码格式。

寄存器路径与栈求值器共用 `apply_unary` 和 `apply_binary`，并使用表达式源码行报告错误。短表达式、短路运算、built-in、字符串拼接、随机操作，以及无法证明为直线结构的表达式，继续使用规范的 `ExprOp` 栈路径。可复用的 `Option<Value>` 工作区避免重复求值时为临时寄存器反复分配；最终值仍在写入帧前经过正常的资源指标计算。

计划为每个操作携带小型类型提示。整数运算和布尔取反在运行时值符合提示时使用类型化 helper；若值不匹配，立即回到共享的动态运算器，外部构造的值仍得到相同诊断。逻辑值按 SSA 顺序表示，再通过线性生命周期分配映射到可复用的物理寄存器，在不增加第二套语义表示的前提下保持计划紧凑。

### 简单 built-in 调用在执行准备时特化

若一个表达式只包含若干 `Const` 或 `Load`，最后紧跟一个 `Call`，执行元数据会把参数预解析为 `QuickenedOperand::Constant` 或 `QuickenedOperand::Slot`。运行时无需再次解释这些取值指令。

对于只读的 `len`、`get` 和 `contains`，VM 直接借用常量池或帧槽位中的 `Value`，使用按参数数量构造的栈内引用数组调用 `velin-eval`。这条路径不会先克隆集合或字符串的 `Arc`。

需要消费或修改所有权的 `list`、`record`、`push`、`put` 和 `remove` 继续走可复用操作数栈。固定参数 built-in 直接从栈顶弹出操作数；`list` 在参数占满整个栈时可以接管该 `Vec` 作为结果存储。复杂参数表达式始终使用普通 `ExprOp` 求值。

借用路径、所有权路径和普通 evaluator 最终共享同一 built-in 实现及错误规则。

### 自更新利用写时复制

`Value::String` 使用 `SharedString(Arc<String>)`，列表和记录分别使用 `Arc<Vec<Value>>` 与 `Arc<BTreeMap<...>>`。读取、变量别名和机器快照只增加引用计数。

自更新在完成预检后通过 `Arc::make_mut` 修改值：

- 只有一个所有者时复用原分配；
- 存在变量别名或 `Machine::clone` 快照时复制底层数据；
- 更新完成后，旧别名仍观察到原值。

这使值语义与存储复用兼容。不能把“同一槽位”直接等同于“唯一所有者”，真实的 `Arc` 引用计数才是所有权依据。

### 资源指标随值流动

`DataMetrics` 同时记录值树的节点数、UTF-8 文本字节数和最大嵌套深度。表达式和 built-in 返回 `(Value, DataMetrics)`，赋值时把两者一起写入帧。帧为每个槽位维护紧凑的 footprint 与 depth 数组，并维护整台机器的聚合 footprint。

直接常量、变量复制和普通表达式结果可以复用已有指标。集合编辑通过“旧指标减去被移除项，再加上新项”更新节点数与文本量。深度采用保守增量规则；只有移除当前最深子项且新项不足以维持原深度时，才重新扫描结果值树。

逻辑资源计数与 `Arc` 是否共享无关。同一个集合被多个槽位引用时会按每个逻辑值分别计入预算，因此执行结果不依赖瞬时所有权状态。

## 有意保留的成本

以下成本服务于正确性、API 边界或可维护性，不应仅为了微基准而消除：

- 任意外部 `Program` 在进入 VM 前执行完整验证。
- `Machine::clone` 复制密集的槽位和指标数组，使两个机器可以独立推进；嵌套字符串和集合仍共享底层 `Arc`。
- 存在真实别名时，集合和字符串更新执行写时复制。
- 宿主调用把参数收集为拥有所有权的 `Vec<Value>`，因为值需要跨出 VM，并且要在 yield 期间存活。
- 宿主载荷逐项累计资源指标，确保总值数和文本量不超过边界。
- 静态检查保留保守合流和精确源码诊断，不用不可靠的推断换取少量吞吐。
- 不能证明等价的表达式始终使用通用字节码路径。

判断新的性能设计是否值得保留时，应同时检查代码局部性、语义来源数量、回退路径、失败原子性和测试覆盖，而不是只看某一个基准数字。

## 性能验证

性能测试按阶段拆分，避免把不同成本混在同一个结论中：

| 基准前缀 | 覆盖范围 |
| --- | --- |
| `check/*` | 控制流构建、确定赋值和类型传播 |
| `compile/*` | 解析后的 lowering、表达式编译和程序布局 |
| `machine/*` | 字节码验证证明复用、元数据和帧初始化 |
| `vm/*` | 已构造机器上的执行路径 |

CLI 计时包含进程启动、源码解析、lowering 和检查，适合观察完整工具体验；Criterion 在同一进程中重复目标路径，适合定位具体机制。两者回答的问题不同，记录结果时应注明机器、Rust 工具链、构建模式和计时边界。

先运行正确性与静态质量检查：

```sh
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
```

运行完整 Criterion 套件：

```sh
cargo bench -p velin --bench pipeline -- --noplot
```

按机制选择聚焦基准：

```sh
cargo bench -p velin --bench pipeline -- check/wide_linear_script --noplot
cargo bench -p velin --bench pipeline -- machine/create_wide --noplot
cargo bench -p velin --bench pipeline -- 'wide_linear|constant_folding' --noplot
cargo bench -p velin --bench pipeline -- 'vm/(counter_loop|builtin_loop|growing_list|growing_string|string_reads)' --noplot
```

性能结果必须与语义测试一起解释。对共享语义、所有权或资源统计的调整，还应运行 evaluator 与 VM 的差分测试、别名测试、失败后状态测试以及序列化往返测试。
